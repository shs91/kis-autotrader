## 현상 분석

실전(real) 전환 후 ~2주(2026-05-29 ~ 06-11) 데이터 기준. **부진의 원인은 "리스크 게이트가 막아서"가 아니라 "살 종목이 사실상 없어서"다.**

### 매매 퍼널 (실측)

| 단계 | 수치 | 해석 |
|------|------|------|
| 일일 스크리닝 | ~2,300종목/일 → 후보 ~5종목 | 조회는 정상 작동 |
| 앙상블 시그널(2주) | **11,431건 생성** | |

| └ BUY | 4,525건 · 평균 conf 0.55 | **전부 단일 종목(대한해운 005880)** |

| 매도 | 1건 → **-3.67% 손절** | |
| 청산 게이트 발동 | 손절 1회 / MDD 0 / 연패 0 | **거의 미발동** |

### 근본 원인 2가지

1. **스크리너 ↔ 전략 미스매치 (핵심).** 스크리너 가중치가 등락률(`WEIGHT_CHANGE_RATE=0.4`, `CHANGE_RATE_MAX=+15%`)에 치우쳐 **급등주**를 주로 선별한다. 그런데 앙상블 하위 전략 중 RSI·볼린저는 평균회귀형이라 급등주를 **"과매수 → SELL"**로 판정한다. 결과적으로 후보의 60%가 매수 불가 SELL로 버려지고, BUY가 뜬 종목은 2주간 **단 1개**였다.

2. **앙상블 단독표 억제(`n_win≥2`).** 같은 종목·같은 봉에서 2개 전략이 동시에 BUY로 겹친 사이클이 0건이었다(개별 BUY표는 MACD·RSI·MA 각각 수천 건 존재). → 오늘(v0.10.0) 이 부분을 **단독 BUY 조건부 허용**으로 패치함(아래 참고).

### 오늘 적용된 패치 (v0.10.0, 2026-06-12 13:37) — 본 제안의 출발점
- `ensemble.py`: `n_win=1` 단독 BUY를 종합 신뢰도 ≥ `solo_buy_min_confidence`(기본 **0.70**)이면 허용. SELL/HOLD는 억제 유지.
- 즉 **진입 완화 메커니즘이 이미 "설정 파라미터"로 노출**되었다. 다만 임계 0.70은 일반 신뢰도 상한(~0.6대)보다 높아 **여전히 빡빡**하다(강한 단독표 084650 0.86·093370 1.0 정도만 통과).

→ 따라서 본 제안은 **추가 코드 변경 없이** ① 단독 BUY 임계를 더 낮추고 ② 스크리너를 전략 친화적으로 재정합하며 ③ 후보·회전·포지션을 확대하여 "아주 공격적" 진입을 달성한다.

### 익절·청산 로직 구조 (유지 대상)

운영자 확인 요청 반영. `engine.py::_process_held_stock`의 매도 우선순위:

1. **손절** — 평균단가 대비 -2%(`MAX_LOSS_RATE`, 실제 .env)
2. **마감 청산 게이트** — 이익(≥1.5%) 포지션 한정, 마감 임박 시 실현
3. **트레일링 스톱 / 고정 익절 (분기, 택1)**
   - `TRAILING_STOP_ENABLED=true`(현재): **트레일링만 평가** — 평균단가 +5%(`TRAILING_ACTIVATION_RATIO`) 도달 시 무장 → 고점 대비 -5%(`TRAILING_DRAWDOWN_RATIO`) 되돌림 시 매도
   - `false`일 때만: 고정 익절(`TAKE_PROFIT_RATIO` 5%) 폴백
4. **전략 매도** — 데드크로스 등

→ **핵심: 트레일링이 켜진 현재, `TAKE_PROFIT_RATIO`는 호출되지 않는다(휴면).** 운영자가 유지를 원한 "+5% 상승 후 추적, 고점에서 되돌림 시 매도" 동작 = 트레일링 스톱이며, **본 제안은 이 로직과 3개 파라미터(`TRAILING_STOP_ENABLED`·`TRAILING_ACTIVATION_RATIO`·`TRAILING_DRAWDOWN_RATIO`)를 일절 변경하지 않는다.** 직전 초안의 `TAKE_PROFIT_RATIO` 0.03 인하안은 ① 트레일링 활성 중 무효이고 ② 트레일링을 끄게 될 경우 추적 이익을 과도하게 앞당겨 깎으므로 **철회**한다.

## 제안 내용

진입 3축을 동시에 푼다. **청산 게이트는 전부 불변.**

- **축 1 — 단독 BUY 문턱 인하**: `STRATEGY_SOLO_BUY_MIN_CONFIDENCE` 0.70 → **0.45**, `STRATEGY_MIN_CONFIDENCE` 0.20 → **0.05**. 중간 강도 단독 BUY(0.45~0.70)가 진입 전환된다. 너무 약한 표(~0.2 이하)는 여전히 거른다.
- **축 2 — 스크리너 정합**: 점수 가중치를 등락률 중심 → **전략 점수 중심**으로 이동(`WEIGHT_STRATEGY` 0.3→**0.5**, `WEIGHT_CHANGE_RATE` 0.4→**0.2**, 합=1.0 유지). 등락률 상단을 +15%→**+8%**로 낮춰 이미 과열된 급등주 추격을 줄이고, 하단을 -3%→**-8%**로 넓혀 **눌림/과매도 종목**(평균회귀 전략이 BUY하는 셋업)을 후보에 포함시킨다. → SELL-only 후보 비중이 줄고 BUY 가능 후보가 늘어난다.
- **축 3 — 후보·회전·사이즈 확대**: 후보 풀 확대(`TOP_N` 30→**50**, `MAX_SCREENED` 10→**20**, `MIN_SCORE` 0.15→**0.10**), 후보 재탐색 가속(`INTERVAL_CYCLES` 30→**15**), 포지션 확대(`MAX_POSITION_RATIO` 0.2→**0.3**), 종목당 당일 재진입 1회 추가(`MAX_DAILY_TRADES_PER_STOCK` 2→**3**), RSI 매수 문턱 소폭 상향(`RSI_OVERSOLD` 35→**38**). **회전율 상승은 전적으로 진입 측에서 나오며, 익절·청산 로직(트레일링 스톱)은 그대로 둔다**(아래 § 익절·청산 로직 참고).

### 투자 잔고 100만원 기준 포지션 사이징 & 매수 상한가

- **잔고(예수금)는 설정값이 아니라 실계좌 값이다.** 시스템은 KIS API 예수금을 그대로 읽어 사이징한다(`risk.calculate_position_size`). 따라서 "잔고 100만원"은 **운영자가 실계좌에 100만원을 예치**하면 자동 반영되며, config로 잔고를 지정하는 키는 없다.
  - ⚠️ 계좌에 100만원을 **초과**하는 현금이 있으면 봇은 그 전액을 사이징 기준으로 사용한다(자본을 100만원으로 제한하는 '자본 상한' 기능은 현재 없음). 봇이 정확히 100만원까지만 쓰게 하려면 별도 코드 기능이 필요하다(원하면 후속 제안).
- **포지션 사이징 수식**: `수량 = floor(예수금 × MAX_POSITION_RATIO ÷ 주가)`
  - 1,000,000 × 0.3 = **포지션당 최대 300,000원**. 동시 보유 약 3종목(0.3×3=0.9) 수준.
- **매수 상한가(`SCREENING_MAX_PRICE`) 20,000 → 150,000**: 현재 상한이 **2만원**이라 2만원 이하 종목만 스크리닝된다(대한해운 2,080원이 유일하게 매수된 핵심 원인). 100만원×0.3=30만원 예산이면 30만원 이하까지 매수 가능하므로, 상한을 150,000으로 **올려 유니버스를 대폭 확대**한다(상한 종목도 최소 2주 매수 가능, 국내 유동 종목 대부분 포함). 30만원 초과는 1주도 못 사므로(`zero_quantity`) 예산(300,000) 이하로 둔다.
  - 더 넓히려면 300,000까지 가능(예산=1주). BRIDGE 범위 100,000~1,000,000 내.

### 코드 변경 — 불필요(권장)

오늘 v0.10.0이 앙상블 진입 완화를 이미 설정 파라미터(`solo_buy_min_confidence`)로 노출했다. 따라서 "앙상블 로직 완화"는 **코드 수정 없이 파라미터 인하만으로 달성**된다. 실거래 중인 시스템에 불필요한 코드 리스크를 추가하지 않기 위해 본 제안은 config 변경만 포함한다.
- (선택, 비권장) 더 공격적으로 가려면 `ensemble.py`에 `n_win_buy` 별도 설정화 또는 BUY 한정 3/4-HOLD 게이트 우회를 도입할 수 있으나, 현 단계에서는 파라미터 튜닝으로 효과를 먼저 관측한 뒤 판단하는 것이 안전하다.

## 기대 효과

- **진입 빈도 증가**: 단독 BUY 문턱 0.70→0.45 + 전략 친화 스크리닝으로, 그간 0건이던 BUY 전환이 일 수 건 수준으로 늘어날 것으로 기대(정확한 폭은 forward 관측 필요).
- **SELL-only 낭비 축소**: 후보 구성이 전략 점수 중심으로 이동해 "미보유 SELL"(현재 60%) 비중이 감소.
- **회전율 상승**: 진입 증가 + 재진입 허용(`PER_STOCK` 3) + 후보 재탐색 가속으로 매매 회전이 빨라짐. **익절·청산(트레일링)은 불변.**
- 수익률 자체에 대한 보장은 아니며, **승률 하락·변동성 상승**을 동반할 수 있다(아래 리스크 참고).

## 리스크 / 비용 경고

- **거래비용 드래그**: 진입이 늘면 매매 건수가 증가해 **왕복 비용(수수료+세금+슬리피지 ≈ 0.2~0.4%)** 누적이 커진다. 단독·저신뢰 진입이 늘면 승률이 50% 아래로 내려갈 수 있고, 이 경우 비용 포함 기대값이 음(-)이 될 위험이 있다. 청산은 트레일링(+5% 무장 / 고점 -5% 되돌림)·손절(-2%) 유지. 실제 첫 거래도 -3.67%(손절)로 종료됐고 슬리피지 계측이 켜져 있다.
- **소액 관측 권장**: 실전 2주차·소액 계좌 단계이므로, 공격적 진입을 켜되 **포지션은 작게 시작**해 1~2주 forward 관측(v0.10.0의 `[매매 진단]` 알림 활용) 후 단계적으로 확대하는 것을 권장. `MAX_POSITION_RATIO 0.3`이 부담되면 0.2 유지도 가능.
- **손절 유지가 핵심**: "작은 손해 감수"는 손절(MAX_LOSS_RATE 0.03)을 켜둬야 성립한다. 진입을 늘리면 나쁜 진입도 늘어나므로 손절은 오히려 더 중요하다. 본 제안은 의도적으로 청산 게이트를 건드리지 않는다.
