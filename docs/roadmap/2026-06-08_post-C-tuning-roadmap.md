# 매매 튜닝 로드맵 — C(매매 진단 알림) 이후

- 작성일: 2026-06-08
- 성격: **지도(가이드) 문서** — `docs/proposals/` 밖이므로 자동 파이프라인이 구현하지 않는다.
- 선행 완료: C(매매 진단 알림) v0.9.0 머지·배포(PR #51). signals 0건=생존편향 규명 완료.

## 배경

실전 가동 이래 매매가 구조적으로 멈춰 있다(누적 체결 2건, 6/2 이후 신규 매수 0). 근본 원인(코드 확정):
1. **발굴 빈약** — 스크리닝 candidate ≈ 0/사이클 (`min_score` 컷 + 약세장 점수 산식)
2. **모니터링 전원 HOLD** — 통과한 소수 종목도 앙상블 신뢰도 0 (단독표 억제 `n_win≥2`)
3. **stale 잔류** — 09시 1회 통과 종목이 `_screened_codes`에 종일 박힘(`clear()`는 장 시작 전만)

> 이것은 *장애*가 아니라 6/1 필터 강화·5/11 임계 상향의 *의도적 보수화* 결과다. 따라서 완화는 "더 많이 거래"는 시킬 수 있어도 "더 잘 번다"는 보장이 없다 — 반드시 측정 기반으로 진행한다.

## ⚠️ 자동 파이프라인 주의 (가장 중요)

`docs/proposals/`에 **`상태: ready`로 두면 다음 auto-implement 사이클이 사람 승인 없이 자동 구현**한다(BRIDGE_SPEC §599). 아래 Phase 2 파라미터는 전부 BRIDGE 허용 범위 안이라 ready면 **실전 자금에 즉시 자동 적용**된다.

| 레버 | 운영값(config_overrides) | 목표 | BRIDGE 허용 |
|------|------|------|------|
| `SCREENING_MIN_SCORE` | 0.15 | 0.10 | 0.1~0.8 |
| `STRATEGY_MIN_CONFIDENCE` | 0.20 | 0.15 | 0.05~0.5 |

**규칙:** 각 Phase 제안서는 처음에 **`상태: draft`(자동 미픽업)**로 작성하고, baseline 측정 후 **한 번에 하나씩 `ready` 승격**(사용자 승인 시)한다.

## 진행 원칙

1. **한 제안서 = 한 레버** (효과 격리). `MIN_SCORE`만 / `MIN_CONFIDENCE`만 분리.
2. **측정 → 적용 → 재측정.** C의 `[매매 진단]` 알림이 매일 계기판(발굴/후보/max_conf/차단/잔고).
3. param은 `config_overrides.json`(BRIDGE §84), 코드(산식·만료)는 5파일+테스트 규칙.
4. 불변 유지(과매매 방지): **위험종목 배제**, 앙상블 **`n_win≥2` 단독표 억제**.

## Phase 0 — 계기판 ON + baseline 관측 (즉시, ~1주)

- ✅ C v0.9.0 배포 완료. 운영자 액션: `com.kis.autotrader` 재시작(장 마감 후).
- **할 일:** `[매매 진단]` 알림으로 며칠간 baseline 축적 — 매일 발굴 후보수, max_conf 분포, 매수게이트 차단 분포.
- **산출:** "정상 보수화 vs 과보수" 판정 데이터. Phase 2 레버 우선순위 확정.

## Phase 1 — 관측성 잔여 정리 (가벼움)

- ✅ signals 0건 = 생존편향 규명 종결(`_record_signal_to_db`가 HOLD/conf<0.20 미저장).
- **남은 것:** `event_logs` 공백(제안서 `2026-06-06_event-logs-error-integrity.md`) — ERROR 적재 경로만 별도 확인. signals와 무관 확정.

## Phase 2 — A-1: 스크리닝/신뢰 완화 (측정 기반, draft→ready)

레버 우선순위(각각 별도 draft 제안서):
1. **`SCREENING_MIN_SCORE` 0.15→0.10** (param_tuning) — 발굴 후보 확대. 위험종목 배제 유지 확인.
2. **`change_rate_score` 음수구간 산식** (코드, `src/strategy/screener.py`) — 약세장에서 등락률 음수→0이 과한지 완화. *코드 변경이므로 BRIDGE 5파일+테스트 규칙.*
3. **`STRATEGY_MIN_CONFIDENCE` 0.20→0.15** (param_tuning) — 단, 현재 conf=0이라 단독으론 무효. ①②로 conf>0가 나온 뒤에만 의미.

- **제약:** ensemble 사전 백테스트 불가(`run_backtest`=MA만). → `config_overrides` 소폭 적용 + 진단 알림 전후 비교 + 소액 실측.
- **게이트:** 한 레버 적용 → 2~3일 진단 관측 → 매매 빈도·승률 확인 → 다음 레버.

## Phase 3 — B: stale 종목 장중 만료 (코드, A-1 결합)

- `src/engine.py`: 장중 `converted=false`가 N사이클 연속인 종목을 `_screened_codes`에서 만료.
- **단독 금지:** B만 하면 모니터링 0 위험. **A-1로 신규 발굴이 들어오는 상태에서만** 적용(죽은 종목 비우고 회전).
- 진단 알림으로 모니터링 회전율 관측.

## Phase 4 — 측정·결정

- A-1+B 적용 전후 비교: 매매 빈도, **승률**, MDD, 평균 손익.
- **승률 개선 없으면 롤백**(`config_overrides`에서 키 제거, BRIDGE §109). 현 보수성 존중.
- 유일한 실거래 데이터포인트(6/2 매수→6/5 -3.67% 손절)는 완화가 수익으로 이어진다는 근거가 아님 — 데이터로만 판단.
